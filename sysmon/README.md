# sysmon

把 **OKX 合约持仓与策略机器人**伪装成一台 Windows 任务管理器的终端看板。

界面长得像系统监控工具，进程列表里是一条条 `svchost.exe`、`WeChat.exe`、`BTC-cpu`……
实际上每一行都是你的一个真实持仓或策略机器人。
CPU / 内存 / 磁盘 / 网络 / GPU 五列**都是 1:1**——显示的数字就是真实数值本身，只是换了个单位；
最后两列还能直接读出**实时价格与持仓均价**。

纯 Go 编写，**零第三方依赖**，单个 exe 直接跑。

读法示例：`BTC-cpu` 那一行就是 BTC 永续持仓——CPU 3.5% 即收益率 3.5%、内存 1.2 GB 即占用保证金 1240 U、
磁盘 468 MB/s 即浮动盈亏 412 U、GPU 10% 即 10 倍杠杆。**数字本身不用换算**。

「趋势」列是盈亏方向的唯一出处：**红 `+` 是盈利，绿 `-` 是亏损**（上面是纯文本快照，实际运行时带颜色）。
监控指标本身都取了绝对值，所以别从数值的正负去判断盈亏。装饰进程和取数失败的记录该列为空。

「性能」页是 CPU / 内存的历史曲线加各"进程"的占用条；「详细信息」页才会显示真实标的与盈亏，
如果不想暴露，把配置里的 `show_detail` 设为 `false` 即可让该页签彻底消失。

> 上面三行 `6,339 MB` 是同一时刻 BTC 的现价，`6,123 / 6,181 / 6,241` 是三个 BTC 仓位的开仓均价——
> 看行情就是读这两列，规则见下方[映射规则](#映射规则)。

## 快速开始

```bat
:: 1. 复制配置模板
copy config.example.json config.json

:: 2. 编辑 config.json，填上 OKX 的 api_key / api_secret / passphrase

:: 3. 先自检，确认凭证与映射都没问题
sysmon.exe -check

:: 4. 开跑
sysmon.exe
```

**没有 API Key 也能直接跑**——会自动使用内置演示数据，方便先把界面和映射调顺眼。

![提示] 建议单独申请一个**只读权限**的 OKX API Key，不要勾选交易与提现。

### 命令行参数

| 参数 | 说明 |
| --- | --- |
| `-c <path>` | 指定配置文件路径 |
| `-check` | 只做配置与接口自检，打印映射后的对照表，不进界面 |
| `-dump 118x30` | 把三个页签渲染成纯文本打印出来，预览外观用 |
| `-v` | 显示版本号 |

## 配置说明

配置文件是 **JSON，但支持 `//` 和 `/* */` 注释**，边写边备注很方便。

### `okx` — 接口凭证

凭证也可以走环境变量，避免明文落盘：
`OKX_API_KEY` / `OKX_API_SECRET` / `OKX_PASSPHRASE` / `OKX_BASE_URL` / `OKX_SIMULATED`

### `ui` — 外观

| 字段 | 说明 |
| --- | --- |
| `title` | 窗口标题，默认「任务管理器」 |
| `refresh_ms` | 数据刷新间隔，建议 ≥ 3000（OKX 有频次限制） |
| `theme` | `dark` / `light`，运行时按 `T` 也能切 |
| `cpu_name` / `core_count` / `mem_total_gb` | 性能页展示的硬件信息，**纯装饰**，填成本机真实型号更可信。`mem_total_gb` 要能装下你所有持仓的保证金之和（1 U 保证金 = 1 MB）：保证金总额约 8000 U 填 16 即可，上万 U 建议填 32 / 64，否则内存占比会一直顶在 100% |
| `decoy_count` | 额外混入多少条纯装饰的系统进程，默认 8 |
| `show_detail` | 是否提供「详细信息」页签（该页会暴露真实标的） |
| `show_price` | 是否显示最后两列「提交大小 / 页面错误」（真实来源是现价与持仓均价），默认 `true` |

### `processes` — 伪装映射表

每条配置把某个标的或某类策略伪装成一条"进程"：

```jsonc
{ "name": "BTC-cpu", "inst_id": "BTC-USDT-SWAP", "source": "position" }
{ "name": "ETH-cpu2", "inst_id": "ETH-USDT-SWAP", "source": "position" }
{ "name": "nvcontainer", "inst_id": "", "source": "grid" }   // 所有网格策略
{ "name": "", "inst_id": "", "source": "auto" }              // 兜底：把剩下的全铺出来
```

| 字段 | 说明 |
| --- | --- |
| `name` | 界面上显示的进程名。留空则从系统进程名池里自动取一个 |
| `inst_id` | 对应标的，如 `BTC-USDT-SWAP`。留空表示该类别的全部数据 |
| `source` | `position` 持仓 / `grid` 网格 / `dca` 马丁 / `recurring` 定投 / `signal` 信号 / `algo` 条件单 / `auto` 全部 |
| `user` | "用户名"列显示什么，留空用主机名 |
| `pinned` | 置顶显示 |
| `cpu_scale` / `mem_scale` / `disk_scale` / `net_scale` / `gpu_scale` | 各指标的缩放系数，**默认全是 `1`（1:1），一般不用写**；只在想让某列整体放大/缩小时才加 |
| `price_scale` / `avg_scale` | 现价 →「提交大小」、均价 →「页面错误」的缩放系数，默认都是 `0.1` |

一条配置匹配到多条数据时会自动带序号，例如 `BTC-cpu (1)`、`BTC-cpu (2)`。
列表按顺序匹配，先命中的配置优先——把某条特定标的的配置写在 `auto` 兜底条目前面。

## 映射规则

真实数值 → 监控指标。**前五项都是 1:1，不做任何倍率换算**：
界面上那一列显示的数字就是真实数值本身，单位看表头，不需要心算还原。

| 监控指标 | ← 真实数据 | 换算 | 举例 |
| --- | --- | --- | --- |
| **CPU %** | 收益率 | `\|收益率%\|` | 浮盈 3.5% → CPU 3.5% |
| **内存** | 保证金 / 投入本金 | `保证金(U)` → MB | 1240 U → 1240 MB（超 1024 自动显示 1.2 GB） |
| **磁盘** | 浮动盈亏 | `\|浮动盈亏(U)\|` → MB/s | 浮盈 412 U → 412 MB/s |
| **网络** | 24h 涨跌幅 | `\|涨跌幅%\|` → Mbps | 涨 1.83% → 1.83 Mbps |
| **GPU %** | 杠杆倍数 | `杠杆` → % | 10 倍 → 10% |
| **提交大小** | 最新价 | `现价 × 0.1` | BTC 63,385 → 6,339 MB |
| **页面错误** | 持仓均价 | `均价 × 0.1` | 均价 61,230 → 6,123 |
| **趋势** | 盈亏方向 | 只看正负，不看大小 | 亏 1.3% → 绿 `-` |
| **电源使用情况** | — | 由 CPU% 自动分级 | 3.6% → 低 |

前五列之所以 1:1，是因为它们的量级本来就落在真实监控指标的范围内，直接带单位显示最省事，
读表时不用再乘系数。只有最后两列（价格）保留了 `× 0.1`——BTC 现价 63,385 若按 1:1 放进
「提交大小」会变成 61.9 GB，在一台十几 GB 内存的机器上太扎眼。

`cpu_scale` / `mem_scale` / `disk_scale` / `net_scale` / `gpu_scale` 这几个系数仍然保留，
默认都是 1、不用写，只在想让某列整体放大或缩小时才加。

1:1 之后有两处量级要留意，都不是 bug：

- **磁盘列会显得挺忙**：它等于浮动盈亏的原值，几百 U 的浮盈就是几百 MB/s 的磁盘吞吐。
  在一台 CPU 只有 3% 的机器上，持续几百 MB/s 的磁盘 I/O 略扎眼。介意的话给该条（或 auto 兜底条）
  加 `"disk_scale": 0.1`，就是原来的量级。
- **内存列会被保证金撑满**：所有持仓的保证金之和若超过 `mem_total_gb`，性能页的内存占比会贴在 100%。
  把 `mem_total_gb` 调到「总保证金 ÷ 1024」以上即可。

### 怎么看实时价格

最后两列就是给你读行情用的，规则统一：**该列数字 × 10 = 价格**。

| 列 | 读出来是什么 | 说明 |
| --- | --- | --- |
| **提交大小** | 最新价 | 同一标的多条记录数字相同，因为它们共用同一个现价 |
| **页面错误** | 持仓均价 | 用于和现价对照，一眼看出浮盈还是浮亏 |

这两列**不加抖动**，其余指标照旧平滑漂移——它们存在的意义就是数字准，抖一下就偏离真实价格了。

几个已知的边界情况，都不是 bug：

- **策略类记录的均价多为空**：网格 / 马丁 / 定投 / 信号的接口不保证返回开仓均价，条件单更是完全没有，
  这些行的 `页面错误` 会显示 `-`，但 `提交大小`（现价）照常有值。
- **现货标的**的价格来自 `instType=SPOT` 行情，程序会把永续与现货两份行情合并，两类标的都覆盖。
- **价格特别小的标的**（例如 0.05）乘 0.1 后只剩 0.1 MB，读不出有效数字。
  这类标的单独加一条配置把系数放大即可：

  ```jsonc
  { "name": "chrome.exe", "inst_id": "LAB-USDT-SWAP", "source": "position",
    "price_scale": 1000, "avg_scale": 1000 }
  ```

- 终端宽度不足 **112 列**时这两列会自动隐藏（`show_price` 只控制开关，不控制宽度）。

### 关于盈亏的正负

CPU 占用、内存、磁盘吞吐都不可能是负数——真填个 `-3.5%` 的 CPU 占用，界面一眼就假。
所以这些指标一律取**绝对值**，盈亏方向单独由「趋势」列承载：

| 趋势列 | 含义 | 颜色 |
| --- | --- | --- |
| `+` | 盈利 / 上涨 | 红 |
| `-` | 亏损 / 下跌 | 绿 |
| 空 | 平、装饰进程、取数失败 | — |

按 `D` 键可以按方向排序，把所有盈利的排到一起。

所有数值都会叠加一层**平滑的时间抖动**（多段正弦叠加，不是随机数），
所以数字是连续漂移的，看起来就像真实负载在波动，而不是每 3 秒跳一次。

## 快捷键

| 按键 | 作用 |
| --- | --- |
| `←` `→` / `Tab` / `1` `2` `3` | 切换页签 |
| `↑` `↓` | 选择行 |
| `C` / `M` / `N` | 按 CPU / 内存 / 网络排序（再按一次反向） |
| `D` | 按盈亏方向排序，把盈利的排到一起 |
| `P` | 按 PID 排序 |
| `S` / `E` | 按 提交大小（现价）/ 页面错误（持仓均价）排序 |
| `R` | 立即刷新 |
| `T` | 切换深色 / 浅色主题 |
| `Q` / `Ctrl+C` | 退出 |

## 目录结构

```
sysmon/
├── main.go                    入口、-check 与 -dump
├── config.example.json        配置模板（带注释）
└── internal/
    ├── config/                配置加载（支持注释的 JSON）
    ├── okx/                   OKX v5 REST 精简客户端（HMAC-SHA256 签名）
    ├── feed/                  拉取持仓/策略/行情，按配置组装
    ├── fake/                  伪装映射引擎（业务数值 → 监控指标 + 抖动）
    └── tui/                   终端控制、画布渲染、三个页签
```

OKX 客户端是从 `../backend/internal/okx` 抽取精简而来，签名实现与主项目保持一致。

## 说明

- 所有请求都是**只读**的，程序不会下任何单、不会改任何策略。
- 配置文件里的凭证是明文，请注意文件权限；更推荐用环境变量。
- 「详细信息」页会直接显示真实标的与盈亏，公共场合建议 `show_detail: false`。
- 每次刷新会拉**永续与现货两份行情**（都是公开接口，不需要签名），
  这样现货网格、现货定投的标的也能显示出价格；它同时也是「网络」列（24h 涨跌）的数据来源。
- 行情跟随 `refresh_ms` 刷新，默认 3 秒一次，不是逐笔推送。要更接近实时可以把
  `refresh_ms` 调到 1000，但会同时加大持仓与策略接口的请求频率，注意 OKX 的频次限制。
