## OKX 资产分析台（F:/projects/RJDJ）从零搭建
用户需求：OKX 交易数据看板 + AI 分析平台。React 前端 + Go 后端 + SQLite，
OKX 对接参考 goex，需可配置 api_key/secret/passphrase/域名，账号密码登录后看资产、AI 拉数据做分析。

### 关键架构决策
- **后端 Go**：Gin 路由 + GORM + **glebarez/sqlite（纯Go免CGO，因为机器无 gcc）**，
  golang-jwt 鉴权，AES-256-GCM 加密存储 OKX 密钥。
- **OKX 客户端自研**（internal/okx）：对照 goex 的 HMAC-SHA256 + OK-ACCESS-* 头 + timestamp 签名规范，
  支持 Endpoint(域名) 可配，AccountBalance/Positions/Ticker/Candles 均返回接近原生字段。
  理由：goex 高层封装字段精简、持仓仅合约、URI 注入耦合，难以支撑"AI 灵活拉任意数据"。
- **AI**：OpenAI 兼容 Chat Completions + Function Calling，工具 get_account_overview/get_ticker/get_positions/get_candles，
  执行器调用 OKX client。Provider 配置在 backend/.env（LLM_* 变量）。
- **前端**：Vite + React18 + TS + Tailwind + ECharts(饼图) + zustand + react-router + lucide-react。vite proxy /api→8080。

### 关键技术坑
- Windows 无 gcc → mattn/go-sqlite3(cgo) 编译失败，改用 glebarez/sqlite（纯go）。GOPATH 必须用 Windows 绝对路径。
- Go 源码字符串里嵌中文引号会把字符串截断（syntax error），工具描述文案需避免内部 ASCII 引号。
- LLM tool-call 消息 content 需为 null：ai.Message.Content 用 *string。

### 修复：bills-history 拉取报 "json: cannot unmarshal number into ... code of type string"
- 现象：用户其他接口(余额/持仓/策略/行情)都正常，唯独账单流水报错。**不是 API Key 权限问题**。
- 根因：OKX **bills-history 接口的 `code` 字段返回数字 `0`**（其他接口返回字符串 `"0"`），而 client.go 里
  统一响应解析 `wrap.Code string` 是字符串类型 → Go 反序列化崩溃。这也是为什么只有账单接口炸。
- 修复：internal/okx/client.go 新增 `flexibleString` 类型（UnmarshalJSON 剥引号兼容字符串/数字），
  Request 与 PublicRequest 的 `wrap.Code flexibleString`，比较用 string(wrap.Code)!="0"。
- 重启后端：run_in_background 下 `exec ./bin/server.exe`（不带 &），任务保持 running 进程才存活；
  沙箱内用 `&`+disown 或 Start-Process 的后台进程在工具调用返回后会被回收，无法长期驻留。
- 验证：编译通过，后端重启监听 8080，pnl/daily 正常走到业务层返回"未配置 Key"而非崩溃。

### 再修复：bills-history data 为单对象 → "cannot unmarshal object into ... []jsontext.Value"
- 修好 code 后新暴露：OKX bills-history 在无对应类型(SWAP/FUTURES)流水时把 `data` 返回为**单个对象 {} 而非数组 []**，
  Go1.24+ 标准库 encoding/json 底层用 jsontext，报错信息里 []json.RawMessage 显示为 []jsontext.Value。
- 修复：client.go 引入 `okxResp`（Data 用 json.RawMessage）+ `dataList()` 统一规整：data 首字符非 `[`（object/null/缺失）→ 返回空列表，
  数组 → 原样解析。Request 与 PublicRequest 共用，返回签名仍 []json.RawMessage，各 handler 无改动。
- 本地 go run 验证 5 种用例（数字code/object/单对象/数组/null）全部不崩且列表长度正确。
