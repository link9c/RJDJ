# 2026-09-09 工作日志

## OKX 资产分析台（F:/projects/RJDJ）从零搭建
用户需求：OKX 交易数据看板 + AI 分析平台。React 前端 + Go 后端 + SQLite，
OKX 对接参考 goex，需可配置 api_key/secret/passphrase/域名，账号密码登录后看资产、AI 拉数据做分析。

### 关键架构决策
- **后端 Go**：Gin 路由 + GORM + **glebarez/sqlite（纯Go免CGO，因为机器无 gcc）**，
  golang-jwt 鉴权，AES-256-GCM 加密存储 OKX 密钥。
- **OKX 客户端自研**（internal/okx）：对照 goex 的 HMAC-SHA256 + OK-ACCESS-* 头 + timestamp 签名规范，
  支持 Endpoint(域名) 可配，AccountBalance/Positions/Ticker/Candles 均返回接近原生字段。
  理由：goex 高层封装字段精简、持仓仅合约、URI 注入耦合，难以支撑"AI 灵活拉任意数据"。
- **AI**：OpenAI 兼容 Chat Completions + Function Calling，工具 get_account_overview/get_ticker/get_positions/get_candles，
  执行器调用 OKX client。Provider 配置在 backend/.env（LLM_* 变量）。
- **前端**：Vite + React18 + TS + Tailwind + ECharts(饼图) + zustand + react-router + lucide-react。vite proxy /api→8080。

### 关键技术坑
- Windows 无 gcc → mattn/go-sqlite3(cgo) 编译失败，改用 glebarez/sqlite（纯go）。GOPATH 必须用 Windows 绝对路径。
- Go 源码字符串里嵌中文引号会把字符串截断（syntax error），工具描述文案需避免内部 ASCII 引号。
- LLM tool-call 消息 content 需为 null：ai.Message.Content 用 *string。
